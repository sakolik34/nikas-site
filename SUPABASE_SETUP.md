# Nikas Supabase Setup

Этот файл описывает ручные шаги, которые нужно выполнить в Supabase после внесения кода в сайт.

## 1. Создать проект Supabase

Создайте проект в Supabase и скопируйте:

- Project URL;
- public `anon key`.

Вставьте их в `supabase-config.js`:

```js
window.NIKAS_SUPABASE_CONFIG = {
    url: "https://YOUR_PROJECT_REF.supabase.co",
    anonKey: "YOUR_PUBLIC_ANON_KEY",
    productImagesBucket: "product-images",
    mediaBaseUrl: "https://images.nikascompany.com",
    mediaApiBaseUrl: "https://media-api.nikascompany.com",
    edgeFunctions: {
        submitContact: "submit-contact",
        submitProductRequest: "submit-product-request"
    }
};
```

Нельзя вставлять в frontend `service_role` key, Telegram token или другие секреты.

## 2. Выполнить SQL

Откройте Supabase SQL Editor и выполните файл:

```text
supabase/schema.sql
```

Он создаст:

- категории;
- товары;
- изображения товаров;
- варианты объёма и фасовки товаров;
- обычные заявки;
- товарные заявки;
- позиции товарных заявок;
- роли администраторов;
- rate limit таблицу;
- RLS policies;
- legacy Storage bucket `product-images` для старых фотографий;
- seed текущих товаров Nikas без цен.

Файл можно выполнять повторно: он не удаляет заявки и фотографии и не
перезаписывает товары, которые уже изменены через админку. После этого обновления
повторный запуск нужен один раз, чтобы добавить товарам отдельные поля цены на
украинском, русском и английском языках, товарам — отдельные варианты объёма и
фасовки, а позициям заявок — сохранённые фасовку и цену на момент отправки.

Для новых фотографий товаров дополнительно выполните безопасную миграцию:

```text
supabase/migrations/20260826_cloudflare_r2_product_images.sql
```

Она ничего не переносит и не удаляет. Старые фотографии продолжают открываться из
Supabase, а новые после настройки загружаются в Cloudflare R2. Полная пошаговая
инструкция находится в `CLOUDFLARE_R2_SETUP.md`.

Для выбора количества товара выполните ещё одну безопасную миграцию:

```text
supabase/migrations/20260901_product_quantity_modes.sql
```

Она добавляет два независимых режима товара:

- готовые варианты объёма или фасовки, которые заполняет администратор;
- свободный ввод количества покупателем в `л`, `кг` или `т`.

Оба режима можно включить одновременно. Миграция также добавляет к позициям
товарной заявки отдельные поля физического количества и единицы измерения. Она не
удаляет товары, фотографии или старые заявки. После её выполнения повторно
разверните Edge Function `submit-product-request` из актуального файла
`supabase/functions/submit-product-request/index.ts`.

Не запускайте `supabase/schema.sql` повторно после финальной блокировки заявок:
он предназначен для первоначальной настройки. Для уже работающего проекта
применяйте только отдельные файлы из `supabase/migrations/`.

## 3. Создать администратора

1. В Supabase откройте Authentication.
2. Создайте пользователя вручную по email и паролю.
3. Скопируйте `user_id`.
4. В SQL Editor выполните:

```sql
insert into public.admin_profiles (user_id, email, is_admin)
values ('USER_UUID_HERE', 'admin@example.com', true)
on conflict (user_id) do update set
    email = excluded.email,
    is_admin = true;
```

Только пользователи с `is_admin = true` смогут управлять товарами и заявками.

## 4. Развернуть Edge Functions

В папке проекта выполните:

```bash
supabase login
supabase link --project-ref kgamiuygnjqjwujeekza
supabase functions deploy submit-contact
supabase functions deploy submit-product-request
```

Во время `supabase login` откроется браузер: подтвердите вход в свой аккаунт
Supabase. `supabase link` нужно выполнить только один раз на этом компьютере.

После развёртывания не публикуйте сайт сразу. Сначала откройте текущий сайт и
проверьте обе формы: обычную «Связаться» и товарную «Оформить заявку». Каждая
должна появиться в админке. Telegram на этом этапе может иметь статус
«не настроен» — это нормально.

Когда обе проверки прошли, выполните в Supabase SQL Editor отдельный файл:

```text
supabase/migrations/20260828_lock_down_public_requests.sql
```

И только после этого отправляйте в GitHub новый `nikas-api.js` и другие файлы
сайта. Такой порядок не даёт формам перестать работать во время обновления и
закрывает прямую запись в базу.

Если проект создавался по старой версии схемы и функция отвечает `Could not save
request.`, сначала выполните безопасный файл совместимости:

```text
supabase/migrations/20260829_request_functions_support.sql
```

Он только добавляет недостающие технические поля для серверных заявок и не
удаляет ни товары, ни старые заявки.

Эта же миграция сначала отзывает все старые права у скрытой серверной роли
`service_role`, затем выдаёт ей только необходимые операции для Edge Functions.
Посетители сайта и обычные администраторы эти права не получают. Право `DELETE`
на `product_requests` оставлено только для компенсационного удаления незавершённой
заявки, если сервер не смог сохранить её позиции товаров.

## 5. Добавить Telegram Secrets

Telegram подключается только после создания бота. До этого момента заявки всё равно
сохраняются в Supabase и отображаются в админке со статусом «Telegram не настроен».

Когда бот будет готов:

1. Получите токен у `@BotFather`.
2. Добавьте бота в нужный чат или напишите ему личное сообщение.
3. Узнайте `chat_id`.
4. Добавьте оба значения как секреты Edge Functions.

В Supabase CLI или Dashboard добавьте секреты для Edge Functions:

```bash
supabase secrets set TELEGRAM_BOT_TOKEN="YOUR_TELEGRAM_BOT_TOKEN"
supabase secrets set TELEGRAM_CHAT_ID="YOUR_TELEGRAM_CHAT_ID"
```

Также Edge Functions используют стандартные Supabase secrets:

- `SUPABASE_URL`;
- `SUPABASE_SERVICE_ROLE_KEY`.

Публичный сайт вызывает только эти функции. Они проверяют поля формы, ограничивают
частые отправки и сохраняют заявку от имени сервера; браузер не получает права
напрямую создавать записи в таблицах.

## 6. Проверить заявки

Обычная заявка:

1. Откройте `index.html`.
2. Заполните имя и телефон.
3. Отправьте форму в блоке контактов.
4. Проверьте таблицу `contact_requests`.
5. Проверьте Telegram.

Товарная заявка:

1. Откройте `category.html?category=all`.
2. Проверьте товар только с готовыми вариантами фасовки.
3. Проверьте товар только со свободным количеством: например, `12,5 кг`.
4. Проверьте товар, у которого включены оба режима.
5. Откройте заявку и нажмите “Оформить заявку”.
6. Заполните имя и телефон.
7. Проверьте таблицы `product_requests` и `product_request_items`. Для свободного
   количества должны заполниться `amount_value` и `amount_unit`.
8. Проверьте Telegram: выбранная фасовка либо физическое количество должны быть
   указаны рядом с товаром.

Если Telegram не настроен или временно не отвечает, заявка все равно должна
сохраниться в базе, а поле `telegram_status` станет `skipped` или `failed`.

## 7. Проверить RLS

Публичный пользователь должен:

- читать только активные категории, товары и изображения;
- создавать заявки через Edge Functions.

Публичный пользователь не должен:

- читать заявки;
- менять статусы заявок;
- создавать или редактировать товары;
- управлять изображениями;
- видеть скрытые товары.

Администратор после входа в `admin.html` должен:

- видеть товары;
- добавлять и редактировать товары;
- скрывать товары;
- загружать до 10 фотографий товара за раз;
- менять основное фото и порядок галереи;
- включать готовые варианты фасовки, свободный ввод количества или оба режима;
- видеть внизу редактора список ошибок, которые мешают публикации товара;
- видеть оба типа заявок;
- менять статусы, контакты, комментарии, названия товаров и количество в заявках;
- копировать готовую заявку для отправки менеджеру.

## 8. Локальный запуск

Для статической проверки можно запустить:

```bash
python3 -m http.server 8088 --bind 127.0.0.1
```

И открыть:

```text
http://127.0.0.1:8088/index.html
http://127.0.0.1:8088/category.html?category=all
http://127.0.0.1:8088/admin.html
```

Без реальных Supabase URL и anon key публичный каталог работает на fallback-данных, но отправка заявок и админка покажут сообщение, что Supabase еще не настроен.
